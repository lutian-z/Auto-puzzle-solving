# 益智谜题屏幕自动解题合集

六个独立的解谜自动化工具，流程相同：屏幕上框选题目 → 自动识别 → 求解 → 键鼠自动作答提交。配置全部写死在代码里，无命令行参数，作答过程按 ESC 可中断。

## 包含项目

以下命令均在项目根目录执行：

| 目录 | 谜题 | 入口 |
|------|------|------|
| 数独 | 标准 / 异形数独 | `python 数独/main.py` |
| 扫雷 | 扫雷（支持超出屏幕的超大棋盘，滚动拼接） | `python 扫雷/main.py` |
| 高楼 | 摩天楼（Skyscraper） | `python 高楼/main.py` |
| 数墙 | 数墙（Nurikabe） | `python 数墙/main.py` |
| 帐篷 | 帐篷与树（Tents and Trees） | `python 帐篷/main.py` |
| 马赛克 | 马赛克（Mosaic，数字=3×3邻域涂黑数） | `python 马赛克/main.py` |

## 目标网站

题目均来自同一系列的在线解谜站（中文版前缀 `cn.`，英文版为 `www.`），各项目的根站点：

| 项目 | 网站 |
|------|------|
| 数独 | https://cn.puzzle-sudoku.com/ |
| 扫雷 | https://cn.puzzle-minesweeper.com/ |
| 马赛克 | 挂在扫雷站下：https://cn.puzzle-minesweeper.com/ 左侧菜单选"马赛克" |
| 高楼 | https://cn.puzzle-skyscrapers.com/ |
| 数墙 | https://cn.puzzle-nurikabe.com/ |
| 帐篷 | https://cn.puzzle-tents.com/ |

（异形数独在 https://cn.puzzle-jigsaw-sudoku.com/ ，数独项目同样支持。）

## 使用

```bash
# 在根目录安装依赖（一次装齐六个项目）
pip install -r requirements.txt

# 在根目录直接运行任一项目
python 数墙/main.py
```

运行后屏幕出现半透明遮罩，按住左键拖动画框框住整个棋盘（可略大于棋盘，识别会自动裁剪），松开后程序自动完成识别、求解、作答并提交。

## 环境

Python 3.7+，主要在 Windows 上使用（Linux 也可运行）。 ortools 用于数墙/帐篷的 CP-SAT 求解，scipy 用于马赛克的 MILP 求解，缺失时对应项目会自动退化为纯 Python 求解器。

## 变更记录

### 2026-09-22 ~ 09-23 泛化性与性能加固（扫雷之外五项目）

对五个兄弟项目做了只读审计后，落地了一批**可证明不改变现有正确行为**的修改（主路径逐位一致对拍）：

**真 bug 修复**
- **马赛克/数墙/帐篷：去倾斜坐标逆映射方向错**（`recognizer.py` `to_input` 的旋转分支）。实测 warpAffine 的内容移动是 q=M(θ)·p，回原图须用 M(−θ)；旧实现三处各错各的（有的取了反向的"逆"），往返偏差随偏心距线性放大（3° 约 38px）。仅在使用"自动转正"分支时触发（常规截图不倾斜所以一直没暴露）。
- **数独：多显示器 DPI 换算错**（`_physical_scaling` 把主屏逻辑尺寸除以虚拟桌面合集宽高）。六项目统一改为取主显示器 `monitors[1]`（单屏恒等，多屏才修正）。
- **数独：系统字体模板与内嵌/运行时归一化规则不一致**（24 vs 22），同字形匹配分数先天掉 0.1~0.14。统一为 22。

**泛化性兜底（主路径不动，只在原会失败时多试一次）**
- 高楼格线检测、数墙墙体检测：绝对灰度阈值（128）失败时，用"格体众数×0.87"相对阈值再兜底一次（应对浏览器小数缩放下网格线被反锯齿抬亮）。
- 数独：①"已知格低于 0.9n 就不盲解"的护栏（防止整盘读空却被填全 81 格——空盘 solve 确实会返回合法解）；②极性救援：主读已知格过少时，用"格内区对众数偏离图 Otsu"重读一遍，浅灰字/暗底亮字也能读出；③救援同样带置信闸。

**提速（保语义）**
- 全部 Windows 项目启动处加 `timeBeginPeriod(1)`，让毫秒级点击/滚动间隔真正生效（默认 15.6ms 粒度会放大 sleep）。
- 高楼求解器：按 n 缓存全排列左/右可见数数组（旧实现每个约束对重算，占单次求解 96.8% 时间），实测 9×9 提速约 4.4 倍。
- 数独 `best_thin_max`：边厚度从"每个候选阈值重测一遍"改为一次预计算 + 查表并查集，输出逐位一致、实测 2.5 倍。
- 帐篷网格提取：逐组件全图 `labels==i` 布尔比较改为 `keep[labels]` 查表（与马赛克 9/1 优化同构），30 组随机掩码逐位一致。

**未改动（有意保留，避免改变现有正确行为）**：数墙/帐篷/马赛克的"格宽 22~72px 才归一化"分档、各 Canny/Hough 绝对参数、数独模板置信 0.5/0.55/0.6 多值、马赛克/数墙 solver 的 Maximize 语义等——这些一旦改动会影响当前已通过实机测试的正常盘判定，需要真实失败截图作验收基准再动。

### 2026-09-23 作答提速推广：四项目移植 Windows 快速点击路径

扫雷/马赛克已实机验证的 ctypes `SetCursorPos+SendInput` 直发点击（<0.5ms/次，替代 pyautogui 每次 10~20ms 的平台封装开销）移植到落后的四个项目：**数墙、帐篷**（点击循环）与**数独、高楼**（点击+键入，数字/字母键经 SendInput VK 直发，非单键字符自动回退 pyautogui）。点击节奏（click_interval/cell_delay/抖动/ESC 急停）一律保持原值，收益全部来自去掉封装开销与重复的定时器粒度：数墙/帐篷每次点击约省 10~20ms，数独/高楼每格省两次（点击+键入合计约 25~35ms）；按典型规模估算作答段提速约 2 倍上下。非 Windows 及快速路径异常时回退 pyautogui 旧路径；快速路径无左上角 FAILSAFE，由 ESC 急停与坐标越界检查兜底（与马赛克既有约定一致）。

离线对拍：新旧实现抽函数同种子跑（假 pyautogui/假 sleep 记录动作序列），数墙/帐篷/数独/高楼四项目的点击/键入/sleep 序列**逐位一致**。备份 `数墙/automation.py.bak_speed_20260923`、`帐篷/automation.py.bak_speed_20260923`、`高楼/main.py.bak_speed_20260923`、`数独/main.py.bak_speed_20260923`。

量级（作答段，非求解）：纯点击的数墙/帐篷每格省约 10~20ms 封装开销，典型 100+ 黑格可省 1~2s；点击+键入的数独/高楼每格省两次封装（合计 20~35ms）外加 sleep 从 15.6ms 粒度回归真实毫秒值，9×9 满盘作答约提速 2~3 倍。**注意 Windows 快速路径未经沙箱实机验证（无 windll），复用自马赛克/扫雷已实机通过的同款代码；首次实机作答建议留意有无漏点，异常即回退（快速路径初始化失败会自动走 pyautogui 旧路径）**。

所有修改文件均有 `.bak_20260923`（扫雷柔化线相关为 `.bak_20260922`）备份在旁，回归脚本 `扫雷/regress_check.py` 传真实截图参数可复跑。

### 2026-09-23 数墙：形状模板彻底移除（任意抠形直通）

新测试题出现 M/H 异形，被识别器的"矩形-四角裁-中间裁"参数化门槛拒绝。排查确认求解与作答链路本来就只吃布尔存在矩阵，卡点只有 `recognizer.py` 一处 `shape_params() is None → 报错`。改为：存在矩阵直通（任意形状免模板免改码），唯一新增硬校验是存在格必须四连通（不连通=海必被分割=必无解，多半是框选漏格，在识别层报明确错误优于求解层报"无解"）。`shape_params` 降级为纯描述；异形题现在显示为"20x15, 自由形状(存在 246 格)"。

回归：常驻脚本 `数墙/regress_shape.py`（8 项，全部离线）——旧可参数化形状新旧识别逐位一致对拍、自由形状在旧代码下确实被拒的反向对照、M 形/螺旋/随机异形盘造题→识别→CP-SAT 求解→独立校验、对角相接形状明确拒绝、真实异形截图端到端。备份 `recognizer.py.bak3_20260923`。

### 2026-09-23 马赛克：浅网格线放宽重试（实机 50×50 报"竖线间距不均匀"）

浏览器小数缩放下，50×50 大盘的交替网格线被反锯齿"漂白"到 181~198 灰（格底才 204，只差几个灰阶），主线色窗口 (78,180) 漏掉近半线条 → 竖/横线只检出 37/51 根、间距 24/47 交替 → 变异系数 0.35 被几何闸拦下。修复沿用"主路径不动、失败多试一次"原则：几何判定抛错时自动把线窗上界放宽到 格底−max(4, 3%格底) 重试一次（识别/锚点定位/涂黑回读三个入口同一策略；两条路都失败仍报原始错误）。该盘实测：放宽后 51×51 线全检出（cv=0.014），识别 0.7s（50×50、1192 数字），MILP 0.04s 唯一解并过独立校验。

回归：常驻脚本 `马赛克/regress_mosaic.py`（6 项，全部离线）——普通深线盘新旧逐位一致、随机浅线盘"旧必挂/新全对+可解"、浅线盘锚点与回读同步救活、噪声图不许被放宽窗误救、真实浅线截图端到端（素材存 `马赛克/测试素材/`）。备份 `recognizer.py.bak2_20260923`。

同日补测（浏览器适应性）：灰度扫描确定并守住两条底线——①放宽档可救到"线芯距格底 ≥8 灰阶"（线芯 196 盘已验证救活；实拍最浅 181 余量充足；再浅到距格底 4 灰阶则物理不可分，回归断言此类盘**必须诚实拒绝而不是错认**——为此新增"假粗格盘"兜底闸：线均匀漏检成双倍格时，格内会出现一格多字/低均匀度混装结构，真实 50×50 素材两判据实测全为 0、假盘断崖触发）。②数墙/高楼/帐篷天然免疫此问题：它们有"格体众数×0.87"相对阈值（≈距白底 33 灰阶的余量），181~198 的浅线都在覆盖内；马赛克独有的坑是区间式线掩码上界=(线+底)/2 先天保守，现已补放宽档。
